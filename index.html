FAQ

        
常见问题

        
关于数据源、安装、权限与边界，这里先回答最常见的几个。

      


      

      

        快速定位
        

      


      

        

          HBG DataHub 到底能查哪些数据？
          
目前接入 6 个数据源：直销（城市级，可下钻到团队/部门/销售）、公司（全量经纪公司，公司为最细粒度）、渠道（开发中）、MDC（销售管理决策系统）、MAX（明细报表导出）、星火（权限内报表直查）。覆盖业绩、达成率、续费率、会员新续、资源、流量线索、竞争格局等 40+ 指标专题。

        


        

          怎么安装？支持哪些 Agent？
          
在 Skills 页用安装器复制命令即可，支持「安装全部」和「按需安装」两种模式。安装器会自动识别当前 Agent 的 Skills 目录——目前 WorkBuddy 已适配，Claude Code、Codex、OpenClaw、Hermes 处于待适配状态；均做 SHA-256 完整性校验。

        


        

          数据安全与权限怎么保障？
          
所有查询都代表当前登录用户，通过内网 SSO 鉴权，只能读到权限范围内的数据，且做到行级权限隔离。越权字段与维度在入口就被拦截。公司版另有「城市全量 / 填报」双数据集权限模型，由初始化时自动探测路由。

        


        

          它会替我做决策吗？
          
不会。HBG DataHub 负责把数据取准、口径对齐、归因定位，结论与建议给你参考，但不替你拍板。每一步的中间结果都会落盘（excel 留底 + HTML 报告），可复核、可追溯。

        


        

          查不到数据 / 取数报错怎么办？
          
按顺序排查：① 重试一次；② 核对当前账号在该平台的数据层级权限（很多「没数据」其实是权限范围问题）；③ 仍不行请联系 HBG 数据应用部 · liwenrui 反馈。注意：取数失败时不要自行改写取数脚本绕过。

        


        

          取数时报 HTTP 302 / 连不上数据接口？
          
一般是当前网络不在公司内网，数据接口要求内网环境。在「神奇管家」搜索安装 EasyConnect，连接公司 VPN 后再重新发起查询即可。

        


        

          登录授权反复失败（一直提示要登录）？
          
授权依赖浏览器里已有的 OA 登录态。把系统默认浏览器设为 Chrome 或 Edge，先在浏览器里登录一次任意公司内部系统，拿到 OA Cookie 后再执行登录即可成功。

        


        

          城市 / 部门名称怎么没识别对？
          
尽量用完整、规范的叫法，比如「上海二手房二区」比「上海二区」更准，最好带上城市前缀。仍然不对就换个说法再问一次。

        


        

          提示没有权限看某个数据？
          
说明该层级的数据不在你账号的权限范围内。联系负责人申请对应权限即可；权限开通后，技能会自动刷新缓存并重试一次。

        


        

          查到空数据 / 显示「未更新」？
          
底层看板数据一般每天 9 点后才会更新。9 点之前查询可能拿到空数据或提示未更新，9 点之后再查一次即可。

        


        

          报告 / 在线链接打不开？
          
链接需要用公司账号登录（58 passport）后才能查看。请先确认已在浏览器登录公司账号，再点开链接。

        


        

          能不能只发 Excel、不带分析文字？
          
可以。直接说「只要 excel，然后发给 XX」，技能就只取数、不附带分析文字。

        


        

          发到美事怎么没发出去？
          
美事发送不支持发给自己，必须指定明确的接收方：发同事写对方 OA 名（如「发给王鹏」），发群写群名（如「发到数据群」）。只说「发给我」会失败，改成指定一个同事或群组即可。

        


        

          取数失败时，为什么不能让我直接改脚本重试？
          
取数走的是验证过的固定路径，自行改写脚本或「换个方式绕过」很容易引入新问题（AI 的归因可能是幻觉）。遇到失败请按上面的排查步骤处理，或直接联系负责人，不要自行修改取数逻辑。
